# M05.5 — Hyperscaler Tier 1 Scrapers (AWS, GCP, Azure)

**Goal.** Three more Tier 1 scrapers, this time against authenticated cloud APIs. The complexity is in credentials and API shape, not in the pattern (M04 set that). Each scraper still returns `list[ScrapedPrice]`.

**Depends on.** M04 (pattern), M05 (provider seeding).

**Definition of done.** Three new scraper modules. `Provider` rows for `aws`, `gcp`, `azure` seeded. Each scraper runs against a recorded fixture in CI; manual smoke against the real API succeeds at least once. ~30 new tests.

### M05.5.T02 — AWS scraper (Price List + Capacity Blocks)

- File: `pricing/scrapers/aws.py`
- Two functions: `fetch_aws_ondemand_skus()` (Price List API) and `fetch_aws_capacity_blocks(instance_type, num_instances, date_range)` (EC2 SDK).
- Use `boto3` (add to `pyproject.toml`).
- Tiers emitted: `on_demand` (per-hour list price for `p4d.24xlarge`, `p5.48xlarge`, `g5.*`, etc.) and `capacity-block-{duration}` (e.g. `capacity-block-14d`).
- GPU map: AWS instance type → our GPU slug, accounting for GPUs-per-instance. `p5.48xlarge` is 8× H100 — so a $98/hr instance price becomes $12.25/hr per GPU. Document this division in the parser.
- Capacity Block pricing returned by `describe-capacity-block-offerings` is dynamic; capture `upfront-fee-USD / (instance_count * duration_hours)` as the per-instance hourly equivalent.

**Fixtures.**
- `pricing/tests/fixtures/aws_pricing_p5.json` — sample Price List API response.
- `pricing/tests/fixtures/aws_capacity_blocks_p5.json` — sample `describe-capacity-block-offerings` response.

**Tests:**
- `test_aws_parse_p5_yields_per_gpu_hourly_after_dividing_by_8`
- `test_aws_capacity_block_amortizes_upfront_over_duration`
- `test_aws_parse_handles_missing_instance_type_gracefully`
- `test_aws_parser_returns_decimals`
- `test_aws_unmapped_instance_type_is_logged_not_dropped_silently`

### M05.5.T03 — GCP scraper (Cloud Billing Catalog)

- File: `pricing/scrapers/gcp.py`
- Endpoint: `https://cloudbilling.googleapis.com/v1/services/6F81-5844-456A/skus` (Compute Engine).
- Auth: service-account JSON via `google-auth` library (add to `pyproject.toml`).
- Parse SKUs whose description matches "A2 instance" / "A3 instance" / "G2 instance" patterns. GCP doesn't expose GPU SKUs separately — they're bundled into accelerator-optimized VM SKUs. Map VM type → GPU slug similar to AWS.
- Tiers: `on_demand`, `cud-1yr`, `cud-3yr` (Committed Use Discounts).

**Fixture.** `pricing/tests/fixtures/gcp_skus_a3.json`.

**Tests:** behavior-named, mirror AWS structure.

### M05.5.T04 — Azure scraper (Retail Prices API)

- File: `pricing/scrapers/azure.py`
- Endpoint: `https://prices.azure.com/api/retail/prices?$filter=serviceName eq 'Virtual Machines' and contains(armSkuName,'Standard_ND')` — pagination via `nextPageLink`.
- No auth (public API).
- Parse `meterName` and `armSkuName` to extract GPU type. `Standard_ND96isr_H100_v5` → 8× H100. Same per-GPU division as AWS.
- Tiers: `on_demand` (`reservationTerm == ""` in response), `reserved-1yr`, `reserved-3yr`.

**Fixture.** `pricing/tests/fixtures/azure_prices_nd_series.json`.

**Tests:** mirror AWS / GCP.

### M05.5.T05 — Register, seed, schedule

- Extend `seeds/providers.yaml`:

```yaml
- slug: aws
  display_name: AWS
  provider_type: cloud
  data_source_tier: realtime_api
  has_api: true
  api_endpoint: https://pricing.us-east-1.amazonaws.com/

- slug: gcp
  display_name: Google Cloud
  provider_type: cloud
  data_source_tier: realtime_api
  has_api: true
  api_endpoint: https://cloudbilling.googleapis.com/v1/

- slug: azure
  display_name: Microsoft Azure
  provider_type: cloud
  data_source_tier: realtime_api
  has_api: true
  api_endpoint: https://prices.azure.com/api/retail/prices
```

- Extend `_SCRAPERS` in `scrape_pricing` command with `aws`, `gcp`, `azure` keys.
- Add Celery tasks `scrape_aws`, `scrape_gcp`, `scrape_azure` and Beat entries (hourly per PRD §10.1, all at minute=4 to stagger from RunPod's minute=3).
- Tasks must catch `botocore.exceptions.ClientError` / `google.auth.exceptions.DefaultCredentialsError` / `httpx.HTTPStatusError` specifically — log them and re-raise to trigger Celery retry. **Do not catch `Exception` broadly** (per `CLAUDE.md`).
