# M05.6 — Pricing Data Pipeline (GH Actions + JSON artifacts)

**Status: complete**

## Problem

M05's live-scrape model had two structural failure modes:

1. **CDN / anti-bot drift bricks scrapers silently.** Lambda Labs moved to lambda.ai (HubSpot), Nebius switched to Next.js Apollo SSR — both rendered BS4 `<table>` parsing useless.
2. **GPU name drift empties the DB silently.** RunPod live API returns `"H100 SXM"` but the fixture used `"NVIDIA H100 SXM"`. Zero rows persisted, zero noise.

Additionally, running scrapers from a developer laptop or a Celery beat container exposes egress IPs to rate-limiting and leaves no page-level audit trail.

## Solution

Decouple **scraping** (when/where data is fetched) from **loading** (when/where it lands in the DB):

- GitHub Actions runs scrapers once a day on a clean runner.
- Each scraper writes a normalized JSON file to `data/pricing/<slug>.json` and commits it back to `main`.
- A new `load_pricing` management command reads those files and persists rows on demand — no network needed.

## Artifacts

`data/pricing/<provider>.json` is the single source of truth for "the last successful scrape of `<provider>`". A failed scrape leaves the previous file in place; data stays fresh on disk.

## Key design decisions

- **Atomic writes**: `write_artifact` writes to `.tmp` then renames, so a partial failure never leaves a half-written file.
- **Decimal serialization**: `hourly_usd` is stored as a string in JSON and `Decimal()`-parsed on read.
- **Timestamp preservation**: `persist_prices` accepts an optional `scraped_at` so `load_pricing` replays the original scrape time rather than `now()`.
- **Placeholder DB env vars**: the workflow exports `DB_HOST=localhost` etc. so `settings.py` imports without a real DB. Hardening this is M07 work (see `spec/QUESTIONS.md`).
- **Partial-failure behavior**: `dump_pricing` logs failing providers, skips overwriting their existing JSON, and exits non-zero. GitHub Actions surfaces the failure while good data still lands.
